# OKB CRM v162 — Unified OKB Filter Center

هذه النسخة مبنية مباشرة على **v161** وتحافظ على المحرك المالي، Signed، المخزون، العمولات، رحلة الأوردر، والصلاحيات الحالية.

## التعديل

تمت إضافة قسم جديد داخل:

`Settings → OKB Filter`

وهو مركز موحّد **للفلاتر فقط** ويحتوي على:

- اسم الحالة الجديدة + زر `＋ إضافة حالة`.
- قائمة الحالات الحالية.
- تعديل اسم العرض.
- تفعيل / إخفاء.
- حذف الفلتر بدون حذف أو تعديل أي أوردر.
- `كل الحالات` ثابتة ولا تُحذف.

## الصفحات الموحّدة

نفس قائمة الحالات ونفس الترتيب تظهر في:

- Dashboard
- صفحات الفروع
- خزنة كل فرع
- خزنة الفروع المجمعة

الحالات الجديدة تطابق قيمة `orders.status` فقط. تعديل اسم الفلتر يغيّر اسم العرض ولا يغيّر قيمة الحالة داخل الأوردرات.

## الحالات الخاصة

تم الحفاظ على شروطها القديمة كما هي، ومنها:

- أوردرات صفر
- استعجال الأوردر
- استبدال الأوردر
- أخطاء
- إثبات دفع
- تحويلات السكرتارية
- تحويلات التحصيل من المندوب

هذه الفلاتر لا تتحول إلى Status عادي ولا تغيّر أي حساب مالي.

## Export

Dashboard وصفحات الفروع تستخدم نفس `getFilteredOrders / getBranchFilteredOrders`، لذلك أي فلتر جديد أو موجود يتم تطبيقه تلقائيًا على الأوردرات التي يتم تصديرها.

## Supabase — خطوة التثبيت المطلوبة

شغّل الملف التالي مرة واحدة في Supabase SQL Editor قبل استخدام إضافة/تعديل الحالات:

`supabase/025_okb_filter_center.sql`

الـMigration:

- ينشئ جدول `okb_filter_statuses`.
- يضيف الحالات الحالية بالترتيب المعتمد.
- القراءة متاحة للمستخدمين المسجلين.
- الإضافة/التعديل/الإخفاء/الحذف للأدمن فقط عبر RLS.
- يضيف الجدول إلى Supabase Realtime إن كانت Publication موجودة، فتنتقل التغييرات للجلسات المفتوحة مباشرة.

إذا لم يتم تشغيل الـMigration، السيستم يستخدم قائمة الفلاتر الحالية كـSafe Fallback ولا يغيّر بيانات الأوردرات، لكن إدارة OKB Filter تظل غير متاحة حتى تثبيت Migration 025.

## نطاق الأمان

لم يتم تغيير:

- Signed logic.
- خصم المخزون.
- Branch Stock.
- المحرك المالي أو تقفيل الخزنة.
- Commission System.
- قيم Status داخل الأوردرات.
- Order journey.
