# OKB v159 — Branch Audit Chat + Back Navigation

مبنية على `OKB_v158_Rescued_Orders_True_Rank`.

## Chat

- رسائل Secretary Audit وFinancial Audit الآلية تقتصر على مدينة نصر، اسكندرية، طنطا والمنصورة.
- الأخطاء والتصحيحات المؤكدة فقط تصل للشات، والتنبيهات تظل في مسار المراجعة المعتاد.
- اختيار شركة خارجية مثل J & T يمنع إرسال رسالة الشات، حتى لو ظل اسم فرع قديم على الأوردر بعد نقله.
- أسماء الفروع الإنجليزية والعربية معترف بها. أوردر الفرع المحفوظ من الداشبورد بدون حقل branch مستقل يُعرف من شركة الشحن الخاصة بالفرع.
- رسائل الشركات القديمة التي تحمل اسم الشركة أو لا تحمل فرعًا معروفًا داخل نص رسالة البوت تُستبعد من عرض المحادثة، آخر رسالة، عداد غير المقروء والتحديث اللحظي. لم تُحذف من قاعدة البيانات.
- الرسائل الشخصية بين المستخدمين وسجل المراجعة الأصلي يحتفظان بمسارهما.

## Back

- زر أخضر مستوحى من المرجع، بكتابة سوداء وسهم أسود. زر Commission يحتفظ بتنسيق أزرار Commission الجولد.
- موجود في جميع الواجهات المطلوبة: Shipping/Branch Rank، صفحات الفروع الأربعة، OKB Abnormal، Doctor Rank، خزنة الفروع المجمعة، Pending، Branch Stock، Settings، Users، Daily Report، Permission، Chat، Activity Log، Product Reports، Secretary Audit، Financial Audit، Commission.
- يرجع لآخر صفحة داخل التطبيق، مع تمييز كل فرع عن الآخر وتمييز Company Rank عن Branch Rank وسياق الخزنة والمراجعة المالية.
- الضغط المتكرر يرجع خلال الزيارات السابقة، ولا ينشئ حلقة بين صفحتين.
- الصلاحيات والفرع تُراجع عند الرجوع، وتُتجاوز الوجهة التي سُحبت صلاحيتها. يستعمل الزر وظائف فتح الصفحات الحالية.
- سجل الرجوع خاص بالمستخدم داخل التبويب الحالي، ويُمسح عند الخروج أو تغيير الحساب. لا يُحفظ بعد إعادة تحميل الصفحة بالكامل، ولا يحتوي على بيانات أوردرات أو مرفقات.
- عند عدم وجود زيارة سابقة، تُستخدم صفحة البداية المسموح بها. لا يخرج الزر إلى موقع خارجي.
- فتح الصفحة بالرجوع يتبع سلوك الفلاتر الحالي لوظيفة فتحها؛ هذه الإضافة ليست حفظًا لمسودات النماذج أو الفلاتر السابقة.
- Refresh بدون سهم في المواضع المحددة، وPending أصبح Refresh بدل تحديث. Hard Refresh يحتفظ بوظيفته الحالية.
- أزرار Users أصبحت خارج الجزء المخفي الخاص بإنشاء Role، حتى تظهر أيضًا للمستخدم المصرح له بصفحة Users؛ إنشاء Role يظل خاصًا بالأدمن.

## نطاق الملفات والتحقق

- الملفات القديمة المعدلة: `index.html` و`js/main.js` فقط.
- ملفان جديدان معزولان: `js/page-navigation.js` و`css/page-navigation.css`.
- `css/style.css` وجميع ملفات Supabase متطابقة مع v158.
- وظائف التسعير، التحصيل، التحقق المالي، قفل اليومية، التقارير، صلاحيات الأدوار والفروع لم تتغير. الإضافات داخل وظائف فتح الخزنة والفرع تسجل الانتقال فقط.
- فحص JavaScript syntax نجح.
- 13 اختبارًا جديدًا لمنطق الرجوع، الصلاحيات، الشات، العدادات ونطاق التغييرات: ناجحة.
- 8 اختبارات الإنقاذ والترتيب من v158 أُعيد تشغيلها على JavaScript الجديد: ناجحة.
- 7 حالات حسابية تشخيصية على المحرك الحالي نجحت، وشملت COD، تحويل، دفع مختلط، Prepaid، إثبات مفقود، عجز التحصيل وحد القيمة 40.
- الاختبارات محلية ببيانات اصطناعية وواجهات قاعدة بيانات بديلة، دون إرسال رسائل حقيقية أو تنفيذ عمليات مالية.
- لم يُختبر العرض المرئي في متصفح كامل: بيئة التشغيل لم تتوفر بها نسخة متصفح، وتعذر تنزيلها. يلزم معاينة الشكل على أجهزة التشغيل قبل تعميم الواجهة.
- لم يُجر اختبار على قاعدة Supabase الفعلية؛ وجود SQL داخل الحزمة لا يثبت تطبيقه على الإنتاج.
