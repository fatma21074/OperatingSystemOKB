# OKB v148 — OKB Abnormal

هذه النسخة مبنية على v147 المصححة التي تتضمن توسيط عناوين وبيانات جميع جداول Commission.

## التعديلات

- الاسم الظاهر في OKB Stores وفي الصلاحيات أصبح OKB Abnormal. مفتاح الصلاحية السابق `stores_report` كما هو، فتظل اختيارات الـ Roles محفوظة.
- كارت «مرتجعات تم انقاذها» بعد المنصورة، في أقصى يسار صف الكروت على الشاشات الواسعة. يعرض أسماء الفروع وأعداد الإنقاذ باللون الأخضر وبخط أكبر. العرض يتكيف مع الشاشات الصغيرة.
- مستخدمو النطاق الكامل يرون الفروع الأربعة؛ الحسابات المقيدة ترى الفروع المتاحة لها وفق شروط التقرير الحالية.
- خيار «مرتجعات تم انقاذها» ضمن قائمة الحالات، وإطار Neon أخضر للأوردرات المنقذة.
- فتح التقرير وReset يختاران Returned. Reset يعيد تاريخ الشهر الحالي أيضًا.
- تكبير أسماء وأرقام كروت التقرير الأخرى.
- «فتح الأوردر» يفتح علامة تبويب جديدة ويبحث عن الأوردر داخل فرعه. الأوردر القديم يُحمّل بتاريخ إنشائه. التبويب الجديد يعيد التحقق من الجلسة وصلاحيات التقرير والفرع.
- Export يحمل اسم OKB Abnormal ويشمل ورقة للمرتجعات المنقذة ضمن النتائج المختارة.

## معنى الإنقاذ ومصدر الرقم

يُحتسب الأوردر مرة واحدة إذا كانت حالته الحالية Signed، ويوجد في `activity_logs` سجل إنشاء أو تعديل أو إلغاء يتضمن حقل الحالة الصريح Returned للأوردر نفسه. إعادة محاولة تسجيل الحدث لا تضاعف العدد. الأوردر Signed العادي، أو الذي كان Cancel فقط، لا يدخل كارت الإنقاذ.

المطابقة تعتمد على معرّف الأوردر؛ السجلات القديمة ذات `order_id` الفارغ تُطابق باستخدام Ticket ID والفرع، مع استبعاد المطابقة الملتبسة. اسم العميل والملاحظات وحدهما ليسا دليلًا على حالة سابقة.

الأحداث القديمة التي لم تُسجل في سجل النشاط لا يمكن إثباتها بأثر رجعي، ولذلك لا تدخل العدد. إذا تعذر تحميل سجل الحالات، يظهر تنبيه و«—» بدل رقم صفر مضلل، وتظل أوردرات Returned وCancel متاحة عند نجاح تحميلها.

فلتر التاريخ يحتفظ بمعناه السابق: **تاريخ إنشاء الأوردر بتوقيت القاهرة**. كارت الإنقاذ يلتزم بالتاريخ والبحث والفرع، ويظل ظاهرًا عند اختيار Returned. تاريخ الإنقاذ نفسه ليس أساس فلتر هذه النسخة.

## نطاق التغيير والتحقق

ملفات التطبيق المعدلة: `index.html` و`css/style.css` و`js/main.js`. تعديل JavaScript محصور في تقرير OKB Abnormal واسم الصلاحية واستقبال رابط الأوردر عند فتح التبويب الجديد. تمت مقارنة بقية الكود والملفات بالنسخة الأساسية وتطابقت دون تغييرات، بما فيها الحسابات والتحصيل والمخزون والعمولات وملفات Supabase.

لا يوجد SQL جديد مطلوب لهذه النسخة؛ تستخدم جدول سجل النشاط الموجود بالفعل. لا تعِد تشغيل ملفات Supabase القديمة لتطبيق هذا التعديل.

نجحت 13 مجموعة اختبارات محلية على الدوال الفعلية، شملت التصنيف ومنع التكرار والصلاحيات وحدود التاريخ والبحث والتصدير وفتح الأوردر القديم والأخطاء وتزامن الطلبات والتحميل بعد أول 1000 سجل. نجح فحص صياغة JavaScript وفحص ترتيب عناصر HTML والتأكد من بقاء إصلاح توسيط Commission.

اختبارات قاعدة البيانات وفتح التبويب استُخدمت فيها محاكاة محلية. لم تُشغّل النسخة على قاعدة بيانات الإنتاج ولم يُجرَ فحص بصري داخل متصفح متصل بها.

للتطبيق، استخدم ملفات هذه النسخة مع إعدادات الاستضافة المعتادة. روابط CSS وJavaScript تحمل رقم v148 لتحديث الملفات عند تحميل الصفحة.
